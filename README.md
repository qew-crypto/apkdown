# ChatGuard — модерация и приём заявок

Новый проект в репозитории `qew-crypto/apkdown`. Старый Telegram → Filebin бот заменён: **здесь больше нет авторизации личного аккаунта, API_ID/API_HASH, скачивания файлов или Filebin**. Нужен только токен своего бота от @BotFather. Это самостоятельный компактный модератор с похожими базовыми функциями, а не копия Ирис.

## Возможности

- Автопринятие **новых заявок** в супергруппы и каналы.
- `/panel` с кнопками **«Принять все сохранённые заявки»**, **«Автоприём вкл./выкл.»**, **«Обновить»**, **«Остановить массовый приём»**.
- Заявки, роли, настройки, варны, триггеры и журнал хранятся в SQLite и переживают перезапуск.
- Пять привилегированных ролей; создатель чата определяется автоматически через Telegram.
- Баны/разбаны, муты/размуты, варны и удаление отдельных сообщений.
- Фильтр ссылок, рекламных пересылок и заданных фраз; антиспам.
- Точные текстовые триггеры: слово/фраза → немедленный ответ.
- Настройки и роли независимы в каждом чате.

## Важное ограничение «принять все»

**Telegram Bot API не предоставляет список всех ожидающих заявок.** Поэтому бот сохраняет полученные `chat_join_request` и массово обрабатывает **только сохранённые заявки**. Заявки, поданные до подключения/назначения бота или не доставленные Telegram, он перечислить не может. Автоматического импорта старого списка нет, личная пользовательская сессия для обхода этого ограничения не используется.

- Автоприём включён по умолчанию. Чтобы накопить очередь, отключите его через панель или `/autojoin off`.
- Включение автоприёма применяется к **новым** заявкам; для накопленных нажмите кнопку массового приёма.
- Массовый приём берёт снимок очереди на момент нажатия. Новые заявки во время обработки идут в следующую партию (либо принимаются автоприёмом).
- Повторно доставленные события не дублируются. Неуспешные заявки остаются в очереди; уже принятые участники убираются при повторной обработке.
- Отменённые пользователями заявки могут остаться в локальном списке: Bot API не присылает полноценную синхронизацию списка. Поэтому счётчик означает сохранённые записи, не гарантированно актуальную очередь Telegram.
- Telegram хранит недоставленные обновления ограниченное время (обычно до 24 часов). Держите бот включённым. После перезапуска база сохраняется, но прерванный массовый приём автоматически не возобновляется — нажмите кнопку снова.

## Запуск

Требуется Python **3.11+** и постоянно включённый компьютер/VPS с доступом к Telegram Bot API.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` в редакторе:

```dotenv
BOT_TOKEN=ваш_токен_от_BotFather
```

Не присылайте токен в чат и не публикуйте `.env`. В Windows используйте `py -3 -m venv .venv`, затем `.venv\Scripts\python.exe -m pip install -r requirements.txt` и `.venv\Scripts\python.exe bot.py`.

```bash
python bot.py
```

Используется long polling, публичный сервер/HTTPS не нужен. Не запускайте второй экземпляр с тем же токеном. Если у этого токена уже установлен webhook, сначала остановите старый сервис и уберите webhook стандартными средствами Telegram: long polling и webhook одновременно не работают. Программа намеренно не удаляет чужой webhook и не отбрасывает накопленные обновления.

### Права Telegram

Добавьте бота администратором:

- **Удаление сообщений** — фильтры и `/del`.
- **Блокировка участников / ограничения** — баны и муты.
- **Приглашение пользователей** — приём заявок, включая канал.

Для заявок создайте ссылку-приглашение с опцией **«Заявка на вступление»**. Для модерации используйте **супергруппу**: ограничения участников в обычных группах могут быть недоступны. В каналах реализованы заявки и управление ими; муты/варны относятся к участникам обсуждения в привязанной супергруппе, которую нужно настроить отдельно.

Бот-администратор должен получать сообщения участников. При проблемах проверьте права и настройку Privacy Mode у @BotFather. Сообщения других ботов Telegram обычно не передаёт. Сообщения анонимных администраторов/от имени каналов не наказываются автоматически. Команды модерации отправляйте от своего личного аккаунта, не анонимно.

## Панель с кнопками

В группе:

```text
/panel
```

Для канала или группы из личного чата с ботом:

```text
/panel -1001234567890
/autojoin -1001234567890 off
/settings -1001234567890
```

Вместо примера укажите настоящий числовой ID своего чата. Бот должен быть в нём администратором. Панель доступна создателю или назначенной роли 4. Право проверяется при каждом нажатии; массовый приём повторно проверяет инициатора каждые 10 записей. Выключение автоприёма не останавливает уже запущенную массовую обработку — для этого отдельная кнопка.

## Роли — ровно 5 привилегированных уровней

| Уровень | Роль | Права |
| --- | --- | --- |
| 5 | Создатель чата | Определяется Telegram автоматически; все возможности |
| 4 | Администратор бота | Настройки, заявки, триггеры, назначение ролей 0–3, все наказания |
| 3 | Старший модератор | Бан/разбан, муты, варны, удаление, журнал |
| 2 | Модератор | Муты, варны, удаление, журнал |
| 1 | Помощник | Варны, снятие одного варна, просмотр варнов |

`0` — участник без привилегий, не шестая модераторская роль. Роли 1–4 назначаются только внутри бота и **не выдают** права администратора Telegram. Обычный Telegram-администратор не получает автоматически роль 4. Создатель назначает её командой. Человек, вышедший/удалённый из чата, не может использовать сохранённую роль для управления им из лички.

Назначение ответом на сообщение:

```text
/role 4
```

Или по ID:

```text
/role 123456789 4
```

Создатель может назначить 4, администратор бота — только 0–3. `0` снимает роль. Изменять равные/старшие роли и собственную роль нельзя. Telegram-администраторов и создателя бот не банит/не мутит; сначала нужно вручную снять их реальные права, если это необходимо. Назначенные роли 1–4 освобождены от автофильтров; Telegram-администраторы и создатель также не наказываются ими.

## Команды

Наказания можно применять **ответом на сообщение** либо указанием **числового ID**. Произвольные `@username` Bot API не разрешает надёжно преобразовывать в ID, поэтому такой способ не поддерживается.

```text
/help
/roles
/myrole

/warn [ID] [причина]
/unwarn [ID]
/warns [ID]
/mute [ID] [10m|2h|7d] [причина]
/unmute [ID]
/ban [ID] [причина]
/unban [ID]
/del                     # только ответом
/log
```

- `/mute` без времени: 1 час. Формат времени: `30s`, `10m`, `2h`, `7d`; диапазон 30 секунд–365 дней. Если указывается причина, сначала укажите время.
- `/ban` — постоянный бан. `/unban` только разрешает вернуться по приглашению, не добавляет автоматически.
- `/unmute` восстанавливает обычные разрешения чата; индивидуальные ограничения, существовавшие до мута, отдельно не сохраняются.
- По умолчанию 3 варна → мут на 24 часа и сброс варнов **только после успешного мута**. Если не хватило прав, варны сохраняются. Помощник тоже может довести счётчик до автоматического мута.
- `/unwarn` снимает один варн. Роли изолированы по чатам.
- Команды от одного пользователя ограничены частотой примерно одна в секунду, чтобы бот не отвечал на командный флуд.

### Фильтры и антиспам (роль 4+)

```text
/links on
/ads on
/spam on
/autojoin on
/warnlimit 3
/settings

/adword add купи подписку
/adword del купи подписку
/adword list
```

Все четыре переключателя по умолчанию `on`.

- **Ссылки:** URL из сущностей Telegram (включая скрытые ссылки), `http(s)`, `www`, Telegram-ссылки, `@упоминания` и некоторые распространённые домены. Анализируются также подписи к медиа. Это эвристика, не полный детектор обфускации; возможны ложные срабатывания. `/links off` выключает её.
- **Реклама:** пересылки с доступным источником-каналом и фразы, добавленные через `/adword`. Список фраз изначально пуст. Фильтр не использует ИИ, не читает текст на изображениях и не гарантирует распознавание всей рекламы. Поиск фраз — подстрокой без учёта регистра.
- **Антиспам:** шестое сообщение за 8 секунд от одного участника → удаление этого сообщения и мут на 5 минут. Фотографии/стикеры/другие медиа тоже считаются; альбом состоит из нескольких сообщений и может сработать как флуд. Счётчики в памяти и сбрасываются при перезапуске. Это не полноценный анти-рейд/CAPTCHA.
- Фильтр удаляет нарушающее сообщение, но не выдаёт за него варн автоматически. Для варнов есть ручная команда.
- Старую историю бот не чистит; Telegram ограничивает удаление старых сообщений. При отсутствии прав ошибки пишутся в журнал процесса без раскрытия токена.

### Триггеры

```text
/trigger add привет | Привет! Правила чата — в закрепе.
/trigger add правила | Не спамить, не рекламировать, уважать участников.
/triggers
/trigger del привет
```

Триггер — **весь текст** сообщения/подписи без учёта регистра и внешних пробелов. `привет` сработает, `ну привет` — нет. Ответы — обычный текст без HTML/Markdown-парсинга. Лимиты: 100 триггеров на чат, 100 символов ключ, 3000 символов ответ. Антифлуд ответов — не чаще одного раза в 3 секунды на чат. Сообщения, удалённые фильтром, триггеры не запускают. Триггеры, начинающиеся с зарезервированных команд бота, использовать не следует.

## Данные и безопасность

В `data/chatguard.db` хранятся ID чатов/пользователей, роли, число варнов, настройки, тексты триггеров, рекламные фразы, журнал причин наказаний и полученные заявки. Полная история сообщений не сохраняется. Журнал может содержать введённые модераторами персональные данные — учитывайте это. База не зашифрована; ограничьте доступ к серверу и резервным копиям. `.env` и `data/` исключены из Git/ZIP.

База и журнал пока не очищаются по расписанию. Резервное копирование SQLite делайте при остановленном процессе или штатным SQLite backup API; простое копирование одного `.db` при активном WAL может потерять последние изменения.

Если раньше использовали старого бота с личной сессией, остановите его. При ненадобности отзовите эту сессию в **Telegram → Настройки → Устройства** и удалите старые локальные файлы. Новый проект их не использует. Старые исходники удалены из актуальной ветки репозитория, но остаются в истории Git; переписывание истории не выполняется.

## Тестирование

```bash
python -m unittest discover -s tests -v
```

Тесты локальные, с SQLite и подменёнными Telegram-вызовами. Они не требуют токена и не меняют живые чаты. Полный сценарий нужно проверить в своей тестовой супергруппе и канале после настройки токена/прав. Бот не развёрнут на хостинге автоматически. GitHub Actions запускает те же тесты на Python 3.11.
