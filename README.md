# apkdown — Telegram → Filebin

Личный бот: отправляете ему файл в Telegram, он скачивает его через вашу пользовательскую MTProto-сессию, загружает на https://filebin.net и присылает ссылки. Прогресс скачивания и отправки обновляется примерно каждые **5 секунд**: объём, процент и скорость за последний интервал. При ограничениях Telegram обновления могут задерживаться. Очень короткая передача может закончиться до первого обновления.

## Требования

- Python **3.11+**, интернет и диск минимум под один обрабатываемый файл плюс 100 МиБ.
- Свои `API_ID` и `API_HASH` с https://my.telegram.org → API development tools.
- Свой бот: откройте **@BotFather**, выполните `/newbot` и сохраните токен.
- Свой числовой Telegram ID для `OWNER_ID` (например, можно узнать у @userinfobot; не передавайте ему коды или пароль). Не путайте с ID бота.
- Аккаунт Telegram с доступом к номеру, кодам входа и 2FA-паролю, если установлен.

Никакие готовые токены или аккаунты не включены в исходники. Номер, код и пароль не нужно присылать разработчику. Ввод через бота допустим только в вашем собственном экземпляре; локальный `login.py` безопаснее.

## Быстрый запуск — Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` локально в редакторе и заполните `API_ID`, `API_HASH`, `BOT_TOKEN`, **`OWNER_ID`**. В `OWNER_ID` укажите ID своего личного аккаунта, не бота. В `MAX_FILE_MB` задаётся локальный лимит в МиБ, по умолчанию 4096. Это не обещание такого лимита у Telegram или Filebin.

```bash
python bot.py
```

### Вход через бота

1. Откройте своего бота с аккаунта, чей ID указан в `OWNER_ID`, и нажмите Start.
2. Отправьте **`/login`**.
3. Отправьте **номер в международном формате**, например `+7...`.
4. Отправьте **код из Telegram через точки**, например `1.2.3.5` → `1235` (или обычными цифрами). Используйте все цифры своего кода; пример не является реальным кодом. Точки автоматически удаляются только из кода, не из 2FA-пароля.
5. Если включена 2FA, отправьте **облачный пароль**.
6. После сообщения об успешном входе отправляйте файлы.

Данные для входа принимаются только от `OWNER_ID` в личном чате. Бот пытается сразу удалить входящие сообщения с номером, кодом и паролем. Удаление не гарантируется и не удаляет возможные копии на стороне Telegram. Процесс входа живёт в памяти 5 минут; `/cancel` его отменяет. Три неверных кода/пароля прерывают вход. При несовпадении ID авторизованного аккаунта доступ отзывается.

**Ограничение Telegram:** пересланный/отправленный в чат код входа может быть аннулирован сервисом. Формат с точками не гарантирует защиту от аннулирования. Гарантировать вход через чат нельзя; приложение не пытается обойти защиту. Если код постоянно истекает, остановите бот и выполните локальную авторизацию:

```bash
python login.py
python bot.py
```

`login.py` запрашивает номер, код и 2FA в терминале (код и пароль скрыты). Сессия сохраняется в `sessions/user.session`; после перезапуска вход повторять не требуется. Пароль и код в `.env` не сохраняются.

Откройте **своего** бота с того аккаунта, которым вошли, и нажмите **Start** / отправьте `/start`. Теперь отправляйте или пересылайте файлы, фото, видео и аудио. Чтобы Telegram не сжимал исходный файл, отправляйте его **как документ**. Пересылка должна быть разрешена владельцем исходного чата; защищённый контент бот не обходит.

Бот должен работать на постоянно включённом компьютере/VPS. Это программа для самостоятельного запуска, а не уже размещённый сервис. Остановить: `Ctrl+C`.

### Windows PowerShell

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните .env в редакторе
```

## Поведение и ограничения

- Только личный чат с ботом и только аккаунт с настроенным `OWNER_ID`. ID сессии должен совпадать с ним. Другие пользователи игнорируются.
- Пользовательская сессия слушает **исходящие медиа именно этому боту**. Она не собирает сообщения из других чатов и не скачивает их автоматически.
- Принимаются новые сообщения во время работы. История до запуска не обрабатывается. Бот отвечает после `/start`; для приёма исходящих сообщений требуется активная пользовательская сессия.
- Файлы обрабатываются последовательно: 1 активный и до 3 ожидающих. `/status` показывает очередь. Альбом — отдельные задания для каждого файла.
- Очередь находится в памяти и теряется при перезапуске; отправьте файл повторно. Прерванные загрузки не возобновляются.
- Скачивание идёт на диск; отправка на Filebin — потоковая, без чтения всего файла в RAM. Скорость отправки означает отдачу данных HTTP-клиенту, не подтверждённые байты на диске Filebin. Готовность подтверждается успешным ответом сервера.
- Сверяются размер и SHA-256, если Filebin возвращает соответствующие поля. При несовпадении успешная ссылка не выдаётся.
- Filebin может блокировать APK и другие расширения, большие файлы, IP-адреса или временно не принимать загрузки. Ограничения не обходятся; автоматической смены расширения нет.
- При сетевой ошибке загрузка автоматически не повторяется: сервер мог уже получить файл. Возможен оставшийся файл на Filebin даже при ошибке/остановке клиента.
- Локальный временный файл удаляется после успеха или ошибки. После аварии питания/`kill -9` проверьте `downloads/` и удалите остатки вручную. Исходное сообщение Telegram не удаляется.
- Текущие ограничения Filebin и срок хранения задаются сервисом. Бот показывает `expired_at` из ответа сервера, если доступно. Это временное хранилище, не резервная копия.

## Безопасность

**Filebin не является приватным облаком: любой обладатель ссылки может скачать файл.** Загружайте только то, что имеете право публиковать. Не отправляйте пароли, документы с персональными данными или Telegram-сессии.

- `sessions/user.session` даёт доступ к вашему Telegram-аккаунту. `sessions/bot.session` также секретен. Не публикуйте их, не передавайте другим и не включайте в резервные копии без шифрования.
- `.env`, `sessions/`, `downloads/` исключены через `.gitignore`. В релизный ZIP включены только исходники, тесты и шаблон конфигурации.
- На Unix новые файлы создаются с `umask 077`. На Windows самостоятельно ограничьте доступ к каталогу правами своей учётной записи. Не запускайте код на чужом/публичном сервере.
- Вход возможен через `/login` в своём боте или локальный `login.py`. При входе через чат номер, код и пароль проходят через инфраструктуру Telegram (бот использует MTProto) и процесс вашего бота. Этот способ менее безопасен, чем локальный терминал. Доверяйте только своему серверу и исходникам. Установите 2FA в Telegram.
- Для отзыва доступа завершите соответствующую сессию в **Telegram → Настройки → Устройства**; при утечке токена бота перевыпустите его у BotFather. Перед повторным входом остановите процесс и удалите локальные сессии.
- Не запускайте несколько экземпляров с одной SQLite-сессией. Для замены аккаунта остановите бот, удалите `sessions/user.session*`, исправьте `OWNER_ID`, перезапустите бот и выполните `/login` снова (либо используйте `login.py`).

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты используют локальный HTTP-сервер и не требуют аккаунта Telegram или отправки файлов на Filebin. Проверяются безопасные имена, формат прогресса, потоковая отправка, HTTP-ошибка, размер и SHA-256. Реальный вход и полный сценарий необходимо проверить после настройки собственных данных.

Протокол загрузки: `POST https://filebin.net/{bin}/{filename}` с сырыми байтами и `Content-Length`; документация: https://filebin.net/api и https://filebin.net/api.yaml.
