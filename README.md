# ChatGuard — модерация и приём заявок

Проект в репозитории `qew-crypto/apkdown`. Старый Telegram → Filebin бот заменён модератором. Для обычной модерации и автоприёма новых заявок нужен только токен @BotFather. Дополнительно можно подключить **свой личный аккаунт через личку бота**, чтобы принять старые заявки. Скачивания файлов и Filebin здесь нет. Это самостоятельный компактный модератор с похожими базовыми функциями, а не копия Ирис.

## Возможности

- Автопринятие **новых заявок** в супергруппы и каналы.
- Опциональный личный аккаунт для серверного приёма **всех ожидающих заявок, включая старые**, после отдельного подтверждения владельца.
- `/panel` с кнопками **«Принять все сохранённые заявки»**, **«Автоприём вкл./выкл.»**, **«Обновить»**, **«Остановить массовый приём»**.
- Заявки, роли, настройки, варны, триггеры и журнал хранятся в SQLite и переживают перезапуск.
- Пять привилегированных ролей; создатель чата определяется автоматически через Telegram.
- Баны/разбаны, муты/размуты, варны и удаление отдельных сообщений.
- Фильтр ссылок, рекламных пересылок и заданных фраз; антиспам.
- Точные текстовые триггеры: слово/фраза → немедленный ответ.
- Настройки и роли независимы в каждом чате.

## Важное ограничение «принять все»

**Telegram Bot API не предоставляет список всех ожидающих заявок.** Поэтому бот сохраняет полученные `chat_join_request` и массово обрабатывает **только сохранённые заявки**. Без личного аккаунта заявки, поданные до подключения/назначения бота или не доставленные Telegram, он перечислить не может. Кнопка Bot API и её локальная очередь по-прежнему имеют это ограничение. **Отдельный режим личного аккаунта** использует штатный пользовательский MTProto API Telegram для приёма всех ожидающих заявок; это не импорт локальной очереди. Настройка ниже.

- Автоприём включён по умолчанию. Чтобы накопить очередь, отключите его через панель или `/autojoin off`.
- Включение автоприёма применяется к **новым** заявкам; для накопленных нажмите кнопку массового приёма.
- Массовый приём берёт снимок очереди на момент нажатия. Новые заявки во время обработки идут в следующую партию (либо принимаются автоприёмом).
- Повторно доставленные события не дублируются. Неуспешные заявки остаются в очереди; уже принятые участники убираются при повторной обработке.
- Отменённые пользователями заявки могут остаться в локальном списке: Bot API не присылает полноценную синхронизацию списка. Поэтому счётчик означает сохранённые записи, не гарантированно актуальную очередь Telegram.
- Telegram хранит недоставленные обновления ограниченное время (обычно до 24 часов). Держите бот включённым. После перезапуска база сохраняется, но прерванный массовый приём автоматически не возобновляется — нажмите кнопку снова.

## Запуск

Требуется Python **3.11+** и постоянно включённый компьютер/VPS с доступом к Telegram Bot API.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` в редакторе:

```dotenv
BOT_TOKEN=ваш_токен_от_BotFather
```

Не присылайте токен в чат и не публикуйте `.env`. В Windows используйте `py -3 -m venv .venv`, затем `.venv\Scripts\python.exe -m pip install -r requirements.txt` и `.venv\Scripts\python.exe bot.py`.

```bash
python bot.py
```

Используется long polling, публичный сервер/HTTPS не нужен. Не запускайте второй экземпляр с тем же токеном. Если у этого токена уже установлен webhook, сначала остановите старый сервис и уберите webhook стандартными средствами Telegram: long polling и webhook одновременно не работают. Программа намеренно не удаляет чужой webhook и не отбрасывает накопленные обновления.

### Права Telegram

Добавьте бота администратором:

- **Удаление сообщений** — фильтры и `/del`.
- **Блокировка участников / ограничения** — баны и муты.
- **Приглашение пользователей** — приём заявок, включая канал.

Для заявок создайте ссылку-приглашение с опцией **«Заявка на вступление»**. Для модерации используйте **супергруппу**: ограничения участников в обычных группах могут быть недоступны. В каналах реализованы заявки и управление ими; муты/варны относятся к участникам обсуждения в привязанной супергруппе, которую нужно настроить отдельно.

Бот-администратор должен получать сообщения участников. При проблемах проверьте права и настройку Privacy Mode у @BotFather. Сообщения других ботов Telegram обычно не передаёт. Сообщения анонимных администраторов/от имени каналов не наказываются автоматически. Команды модерации отправляйте от своего личного аккаунта, не анонимно.

## Панель с кнопками

В группе:

```text
/panel
```

Для канала или группы из личного чата с ботом:

```text
/panel -1001234567890
/autojoin -1001234567890 off
/settings -1001234567890
```

Вместо примера укажите настоящий числовой ID своего чата. Бот должен быть в нём администратором. Панель и управление автоприёмом доступны создателю, назначенной роли 4 **либо текущему Telegram-администратору с правом «Приглашение пользователей»**. Последнему не выдаётся внутренняя роль 4: остальные настройки, роли и команды модерации сохраняют прежние ограничения. Право проверяется при каждом нажатии; массовый приём повторно проверяет инициатора каждые 10 записей. Выключение автоприёма не останавливает уже запущенную массовую обработку — для этого отдельная кнопка.

## Роли — ровно 5 привилегированных уровней

| Уровень | Роль | Права |
| --- | --- | --- |
| 5 | Создатель чата | Определяется Telegram автоматически; все возможности |
| 4 | Администратор бота | Настройки, заявки, триггеры, назначение ролей 0–3, все наказания |
| 3 | Старший модератор | Бан/разбан, муты, варны, удаление, журнал |
| 2 | Модератор | Муты, варны, удаление, журнал |
| 1 | Помощник | Варны, снятие одного варна, просмотр варнов |

`0` — участник без привилегий, не шестая модераторская роль. Роли 1–4 назначаются только внутри бота и **не выдают** права администратора Telegram. Обычный Telegram-администратор не получает автоматически роль 4. Создатель назначает её командой. Исключение по доступу, не по роли: действующий Telegram-администратор с правом приглашения может использовать только панель заявок и переключение автоприёма без роли 4. Человек, вышедший/удалённый из чата, не может использовать сохранённую роль для управления им из лички.

Назначение ответом на сообщение:

```text
/role 4
```

Или по ID:

```text
/role 123456789 4
```

Создатель может назначить 4, администратор бота — только 0–3. `0` снимает роль. Изменять равные/старшие роли и собственную роль нельзя. Telegram-администраторов и создателя бот не банит/не мутит; сначала нужно вручную снять их реальные права, если это необходимо. Назначенные роли 1–4 освобождены от автофильтров; Telegram-администраторы и создатель также не наказываются ими.

## Команды

Наказания можно применять **ответом на сообщение** либо указанием **числового ID**. Произвольные `@username` Bot API не разрешает надёжно преобразовывать в ID, поэтому такой способ не поддерживается.

```text
/help
/roles
/myrole

/warn [ID] [причина]
/unwarn [ID]
/warns [ID]
/mute [ID] [10m|2h|7d] [причина]
/unmute [ID]
/ban [ID] [причина]
/unban [ID]
/del                     # только ответом
/log
```

- `/mute` без времени: 1 час. Формат времени: `30s`, `10m`, `2h`, `7d`; диапазон 30 секунд–365 дней. Если указывается причина, сначала укажите время.
- `/ban` — постоянный бан. `/unban` только разрешает вернуться по приглашению, не добавляет автоматически.
- `/unmute` восстанавливает обычные разрешения чата; индивидуальные ограничения, существовавшие до мута, отдельно не сохраняются.
- По умолчанию 3 варна → мут на 24 часа и сброс варнов **только после успешного мута**. Если не хватило прав, варны сохраняются. Помощник тоже может довести счётчик до автоматического мута.
- `/unwarn` снимает один варн. Роли изолированы по чатам.
- Команды от одного пользователя ограничены частотой примерно одна в секунду, чтобы бот не отвечал на командный флуд.

### Фильтры и антиспам (роль 4+)

```text
/links on
/ads on
/spam on
/autojoin on
/warnlimit 3
/settings

/adword add купи подписку
/adword del купи подписку
/adword list
```

Все четыре переключателя по умолчанию `on`.

- **Ссылки:** URL из сущностей Telegram (включая скрытые ссылки), `http(s)`, `www`, Telegram-ссылки, `@упоминания` и некоторые распространённые домены. Анализируются также подписи к медиа. Это эвристика, не полный детектор обфускации; возможны ложные срабатывания. `/links off` выключает её.
- **Реклама:** пересылки с доступным источником-каналом и фразы, добавленные через `/adword`. Список фраз изначально пуст. Фильтр не использует ИИ, не читает текст на изображениях и не гарантирует распознавание всей рекламы. Поиск фраз — подстрокой без учёта регистра.
- **Антиспам:** шестое сообщение за 8 секунд от одного участника → удаление этого сообщения и мут на 5 минут. Фотографии/стикеры/другие медиа тоже считаются; альбом состоит из нескольких сообщений и может сработать как флуд. Счётчики в памяти и сбрасываются при перезапуске. Это не полноценный анти-рейд/CAPTCHA.
- Фильтр удаляет нарушающее сообщение, но не выдаёт за него варн автоматически. Для варнов есть ручная команда.
- Старую историю бот не чистит; Telegram ограничивает удаление старых сообщений. При отсутствии прав ошибки пишутся в журнал процесса без раскрытия токена.

### Триггеры

```text
/trigger add привет | Привет! Правила чата — в закрепе.
/trigger add правила | Не спамить, не рекламировать, уважать участников.
/triggers
/trigger del привет
```

Триггер — **весь текст** сообщения/подписи без учёта регистра и внешних пробелов. `привет` сработает, `ну привет` — нет. Ответы — обычный текст без HTML/Markdown-парсинга. Лимиты: 100 триггеров на чат, 100 символов ключ, 3000 символов ответ. Антифлуд ответов — не чаще одного раза в 3 секунды на чат. Сообщения, удалённые фильтром, триггеры не запускают. Триггеры, начинающиеся с зарезервированных команд бота, использовать не следует.

## Личный аккаунт: старые заявки

Режим **необязательный**. Если `API_ID`, `API_HASH` и `ACCOUNT_OWNER_ID` пустые, остаётся обычный Bot API бот без подключения личного аккаунта.

### 1. Переменные

Добавьте в `.env` или **Variables / Environment** в панели своего хостинга:

```dotenv
BOT_TOKEN=ваш_токен_бота
API_ID=123456
API_HASH=ваш_api_hash
ACCOUNT_OWNER_ID=123456789
```

- `API_ID` и `API_HASH`: https://my.telegram.org → **API development tools**.
- `ACCOUNT_OWNER_ID`: числовой ID **вашего личного аккаунта**, не бота. Например, можно узнать у @userinfobot; не передавайте ему код/пароль.
- Все три дополнительные переменные должны быть заполнены вместе. Не публикуйте `.env`.

### 2. Вход через бота — без консоли

После обновления кода и перезапуска сервиса на хостинге:

1. Откройте **своего** бота с аккаунта, чей ID указан в `ACCOUNT_OWNER_ID`.
2. В личке отправьте **`/account_login`**.
3. Прочитайте предупреждение и пришлите номер в формате **`+кодстраныномер`**.
4. Пришлите полученный код целиком: `12345` или `1.2.3.4.5`.
5. Если включена 2FA, бот попросит облачный пароль.
6. Дождитесь сообщения «Вход выполнен», затем открывайте панель заявок.

`/account_cancel` отменяет процесс. На вход отведено 5 минут, после трёх неверных кодов/паролей он отменяется. Пароль передаётся без удаления точек/пробелов. Четыре команды `/account_login`, `/account_cancel`, `/account_status`, `/account_logout` зарезервированы как управление входом — если пароль буквально совпадает с одной из них, используйте локальный способ ниже. Из других чатов и от других пользователей данные входа не принимаются. Созданная сессия должна совпадать с `ACCOUNT_OWNER_ID`; при несовпадении новая авторизация отзывается.

**Предупреждение:** номер, код и пароль проходят через инфраструктуру Telegram и процесс вашего бота на сервере. Используйте только свой экземпляр на доверенном хостинге. Бот пытается удалить сообщения с данными перед обработкой, но удаление не гарантируется и не гарантирует отсутствия копий у Telegram. Входящие данные не записываются приложением в БД/лог; телефон и временный хеш кода остаются в памяти только на время входа. Сообщения вне активного диалога входа (например, после тайм-аута) автоматически как секреты не распознаются. Не отправляйте данные другим ботам, разработчику, в группы или в поддержку хостинга.

Telegram может аннулировать код, отправленный в чат. Формат с точками **не гарантирует**, что этого не случится. При постоянном истечении кода или если Telegram предлагает неподдерживаемый клиентом способ входа, гарантировать авторизацию через бота нельзя. Приложение не обходит ограничения Telegram. Не запрашивайте коды многократно при FloodWait.

#### Хостинг без своей консоли

Через веб-панель хостинга можно подключить этот GitHub-репозиторий и указать:

- установку зависимостей: `pip install -r requirements.txt`;
- команду запуска: `python bot.py`;
- переменные: `BOT_TOKEN`, `API_ID`, `API_HASH`, `ACCOUNT_OWNER_ID`.

Это фоновый процесс long polling, не HTTP-сайт: выберите worker/background service или иной поддерживаемый вашим хостингом режим для постоянно работающего процесса. Точные названия полей зависят от площадки. Для сохранения сессии и настроек нужны постоянные каталоги `sessions/` и `data/`; при эфемерном диске после redeploy они потеряются, потребуется вход заново. Номер, код и 2FA **не указывайте в переменных хостинга**. После запуска сервиса весь вход выполняется в личке бота. Сам ZIP/GitHub не запускает сервис автоматически.

#### Запасной локальный вход

Если консоль всё же доступна, это более безопасный путь: остановите `bot.py` и в той же папке/виртуальной среде выполните:

```bash
python account_login.py
python bot.py
```

Код и 2FA вводятся скрыто. Нельзя одновременно запускать локальный вход и бот с одним SQLite-файлом сессии.

### 3. Приём старых заявок

1. Личный аккаунт должен быть администратором нужного канала/супергруппы с правом **«Приглашение пользователей»**. Создателю права доступны автоматически.
2. Сам бот также должен быть администратором. Для панели владелец сессии должен быть создателем, иметь внутреннюю роль 4 либо быть действующим Telegram-администратором с правом «Приглашение пользователей». Это не выдаёт ему роль 4 для других команд.
3. Откройте личку с ботом и нажмите Start. При необходимости проверьте `/account_status`.
4. Откройте `/panel -100ID_ЧАТА` и нажмите **«Старые заявки (личный аккаунт)»**. Эта кнопка появляется, когда дополнительные переменные настроены.
5. Бот прочитает число ожидающих заявок через аккаунт и пришлёт подтверждение **в личку владельца**. Подтвердите за 60 секунд.
6. Отправляется `messages.hideAllChatJoinRequests` с **`approved=True`** для конкретного чата. Это штатный пользовательский API; флаг принятия указан явно. Принимаются все заявки, ожидающие в момент выполнения, включая поступившие между проверкой и подтверждением.

Другие модераторы и администраторы не могут использовать вашу личную сессию, даже с ролью 4 или 5 в другом чате. Проверяются `ACCOUNT_OWNER_ID`, ID самой сессии, права аккаунта и узкий доступ инициатора к управлению заявками в выбранном чате. Одноразовое подтверждение привязано к чату, истекает через 60 секунд и не переживает перезапуск. Запрос приёма не повторяется автоматически после ошибки.

**Приём через аккаунт — одна серверная операция.** Кнопка остановки локальной очереди не отменяет уже отправленный запрос, и отменить принятие участников задним числом нельзя. При сетевой ошибке сервер мог уже выполнить приём: проверьте очередь в приложении Telegram перед повтором. Сообщение об успехе означает ответ сервера, не независимую проверку каждого участника. Число оставшихся заявок — моментальный снимок, оно может измениться сразу после проверки.

Режим аккаунта запускается **только явно кнопкой**, не при старте, не по расписанию и не автоматически при подключении аккаунта. Автоприём новых заявок продолжает работать через Bot API. Локальная очередь и журнал Bot API не синхронизируются с серверным списком аккаунта; старые сохранённые записи можно обработать обычной кнопкой, уже вступившие будут пропущены.

### Отключение и хранение сессии

- `/account_status` — проверка подключённого ID, только владелец в личке.
- `/account_logout yes` — отзыв именно этой личной сессии. После него можно войти снова через `/account_login` без консоли и перезапуска. Обычный бот продолжает работать без личной сессии.
- Всегда можно завершить сессию вручную: **Telegram → Настройки → Устройства**.
- Файл `sessions/join_account.session` даёт доступ к аккаунту шире, чем только заявки. Не передавайте его и не запускайте проект на чужом сервере. Он не зашифрован; на Unix новые файлы создаются с `umask 077`, на Windows ограничьте доступ правами своей учётной записи.
- Сессия и `.env` исключены из Git/ZIP. Не храните их в незащищённых резервных копиях. Учтите, что `.gitignore` не удаляет секрет, уже попавший в историю.
- В этом режиме не запускаются обработчики личных сообщений и не собирается история переписок. Для поиска ID чата библиотека может получить список диалогов и сохранить кэш сущностей в файле сессии.

## Данные и безопасность

В `data/chatguard.db` хранятся ID чатов/пользователей, роли, число варнов, настройки, тексты триггеров, рекламные фразы, журнал причин наказаний и полученные заявки. Полная история сообщений не сохраняется. Журнал может содержать введённые модераторами персональные данные — учитывайте это. База не зашифрована; ограничьте доступ к серверу и резервным копиям. `.env` и `data/` исключены из Git/ZIP.

База и журнал пока не очищаются по расписанию. Резервное копирование SQLite делайте при остановленном процессе или штатным SQLite backup API; простое копирование одного `.db` при активном WAL может потерять последние изменения.

Если раньше использовали старого бота с личной сессией, остановите его. При ненадобности отзовите ту сессию в **Telegram → Настройки → Устройства** и удалите старые локальные файлы. Дополнительный режим этого проекта создаёт отдельную сессию `sessions/join_account.session` и не импортирует старую. Старые исходники удалены из актуальной ветки репозитория, но остаются в истории Git; переписывание истории не выполняется.
